## A. 目盛り・カメラの酔い防止（必須）
1. 根本原因を確認する：`rolling_uneven_media.py` の `_ticks()` は各Xについて地形の表面Zに点を置き投影しているため、追従撮影時に「世界X目盛りのY画素」が地形勾配で上下に動き得る。カメラそのもののZ移動と、目盛り基準の上下変動を混同しない。
2. **画面上の目盛り基線Y座標（px）は各視点で全フレーム固定**。目盛り・文字・スタート/ゴールラベルは縦方向に揺らさない。X位置は保存済み実カメラK/Eから実世界Xを投影した値に基づき、カメラが+Xへ進むと目盛りが左へ移動する。カメラの上下追従はしない（主sideは既存の世界Z固定・真正90°を維持）。oblique/overheadでもHUDは固定画素位置でよい。地形表面の曲がりは**別の物理高度表示・断面**として維持し、HUD目盛りが地表高を表すかのように誤記しない。
3. raw native RGB・元カメラK/E・25fps PTSを保存済みのものから使用。背景・歩行姿勢・地形・高さの物理的変動を消さず、**表示用HUDだけを固定**。全視点で基線Yの最大差 <=1px を自動測定し、目視で画面の不快な上下揺れがないか確認する。
4. 0.5m刻み/1mラベル等は保持。UI文字やマーカーがロボットを覆う場合はHUD領域内で退避。世界座標/移動距離と地形標高の別指標を明示する。

## B. スタート／ゴール／経過時間・成功失敗（必須）
1. **ユーザー提示用の目標を「スタート基準の+X方向へ4.00m」と設定**。既存各runのt=0初期ロボットbase Xを `start_x` とし `goal_x=start_x+4.00m`。地形端・走行可能レーン内であることを既存ログから検証。追加試験の物理評価ゲートではなく**独立したプレゼン用到達目標**であることを明記。過去の20秒runがこの目標で制御されていたかのように記載しない。
2. 開始時から**START 0.00m / GOAL 4.00m / 残距離 / 経過sim秒**を読みやすく固定HUD表示。スタートとゴールの線を、世界X位置に対応する水平方向マーカーとして描く（画像の固定位置で距離を偽らない）。俯瞰/斜めも表示。適度に初期説明静止フレーム（例1秒）、終了結果静止フレーム（例2秒）を派生コピーに付けてもよいが「静止表示・シミュレーション時間外」を明示し、実走行時間とMP4再生時間を混同しない。
3. 既存100Hz物理状態ログ（利用可能な実時刻）で`base_x>=goal_x`の**最初の到達時刻**を判定。初回到達区間の前後サンプル時刻とXを保存。動画は既存25fps生フレームのうち到達直後の最初の実フレームまで採用。フレーム外の到達時刻を新しい実フレームだと偽らず、補間を使う場合は「時刻の推定」と明記。実sim終了後の映像は増やさない。
4. 各既存runの20秒映像内でゴール到達が確認できない場合、**未到達（既存記録は20秒で終了）**とし、時間内未達にする。ゴールまで歩き続けた「新規30秒走行」のふりをしない。将来の新規目標到達run（別工程）では「到達まで継続、最大30秒、転倒/境界逸脱/重大エラー停止」という方針を仕様に書いてよいが、今回実行しない。
5. **距離到達と安全性・旧数値ゲートは別の軸で判定**する。
   - 表示例：`距離ゴール到達（実測xx.xx秒）／旧20秒数値検証PASS・F未確認`。
   - ROLLING c0/c1 はたとえ4m到達しても `距離到達／旧20秒安全判定FAIL（FL_calf 非足接触）` と明示。接触発生時刻が表示範囲に入る場合、物理100Hzログに対応する通知を入れる。0N無荷重接触を「転倒」と誤記しない。
   - 到達前の実転倒・境界逸脱・ソルバーエラー・ログ不足はそれぞれ区別し `FALL`/`OUT_OF_BOUNDS`/`ENGINE_ERROR`/`UNKNOWN` などを表示。動画内の不明時刻・未観測状態を作らない。
   - 元の20秒 A–Eゲートを4m到達の短尺動画から再判定しない。古い評価結果を参照するなら`旧20秒評価の結果`と明示。
6. 最後を唐突に切らず、各試行・各視点の**派生版単独MP4の末尾だけ**結果静止画を約2秒表示。`到達/未到達`、`スタート0→目標4.00m`、`実際の到達・記録終了sim秒`、`進行距離`、`旧検証の数値判定`、`F本人評価未済`、`終了理由`を明示。**原本へ編集を加えず、走行映像の合成・別試行混在・速度変更・疑似走行・不要な最終編集を行わない。**
